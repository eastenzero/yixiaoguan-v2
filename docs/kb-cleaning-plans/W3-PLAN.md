## 三、Kimi 任务设计

### Task W3-1：Tier 1 账号逐个扫描（并行，~12 个 Kimi 任务）

每个 Kimi 任务负责 1-2 个 Tier 1 账号。

**任务模板**：

```
你的任务是扫描以下公众号目录中的所有 .md 文件，按照知识库入库标准进行筛选。

工作目录：C:\Users\Administrator\Documents\code\kb-pipeline\ws3-wechat-articles\articles\{公众号名}\

这是「{公众号名}」公众号的历史文章，对应 KB 分类为 {分类}。

筛选标准（必须全部满足）：
1. 包含可复用的校园服务信息（流程、联系方式、政策、时间表等）
2. 信息不过期（2024年及以后的通知仍有参考价值）
3. 不是纯活动报道（"我校举办XX活动"类新闻丢弃）
4. 不是纯转发/转载其他机构的内容

对每个文件，输出一行：
文件名 | 保留/丢弃 | 丢弃原因(如适用) | 信息摘要(一句话)

特别注意：
- 服务指南类（怎么办理XX、XX流程、XX时间表）→ 优先保留
- 政策解读类（XX规定要点、XX标准说明）→ 保留
- 数据发布类（XX统计报告、就业率）→ 如含具体数据则保留
- 活动预告（含时间地点的讲座/招聘会信息）→ 如为常规活动则保留

最后统计：保留 X 个，丢弃 Y 个。

将结果写入：C:\Users\Administrator\Documents\code\kb-pipeline\ws3-wechat-articles\kimi-reports\scan-{公众号简称}.md
```

### Task W3-2：Tier 2 院系账号抽样评估（并行，~7 个 Kimi 任务）

每个 Kimi 任务负责 3 个院系账号的抽样。

```
你的任务是对以下 3 个学院公众号进行抽样评估，判断是否值得全量处理。

对每个学院：
1. 读取该目录下的 .md 文件列表
2. 随机选取 15-20 篇（均匀分布在不同时间段）
3. 逐篇判断是否含有可入库的校园服务信息

学院目录：
- C:\Users\Administrator\Documents\code\kb-pipeline\ws3-wechat-articles\articles\{学院1}\
- C:\Users\Administrator\Documents\code\kb-pipeline\ws3-wechat-articles\articles\{学院2}\
- C:\Users\Administrator\Documents\code\kb-pipeline\ws3-wechat-articles\articles\{学院3}\

对每个学院输出：
- 抽样篇数 / 有价值篇数 / 有效率
- 有价值文章的典型内容类型
- 结论：建议全量扫描 / 跳过 / 仅提取学院简介

将结果写入：C:\Users\Administrator\Documents\code\kb-pipeline\ws3-wechat-articles\kimi-reports\sample-{批次号}.md
```

### Task W3-3：KB 草稿生成

对 W3-1 标记为"保留"的文章，按公众号/分类合并生成 KB 文档草稿。

与 W2-2 使用相同的输出规范模板，输出到 `04-output/from-wechat/`。

## 四、执行顺序

```
第 1 轮（并行）：
├── W3-1: Tier 1 全量扫描（12 个 Kimi 任务）
└── W3-2: Tier 2 抽样评估（7 个 Kimi 任务）

第 2 轮（依赖第 1 轮结果）：
├── W3-3: 对 Tier 1 保留文章生成 KB 草稿
└── 对 Tier 2 中"建议全量扫描"的院系执行全量扫描

第 3 轮：
└── 所有保留文章合并为最终 KB 文档
```

## 六、去重策略

W3 的公众号文章与 W2 的官网数据有大量重叠（同一部门的官网和公众号发布相似内容）。

原则：
- 官网数据（W2）为基准，公众号文章（W3）作为补充
- 如果 W2 已覆盖某个知识点，W3 的同类文章标记为"已有"跳过
- W3 独有的内容（如时效性通知中的流程说明、公众号独家发布的服务指南）保留
- 在 KB 文档的 sources 字段中同时标注 W2 和 W3 来源

去重在最终合并阶段（`04-output/merged/`）执行，清洗阶段各自独立产出。
