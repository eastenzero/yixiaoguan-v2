## 三、Kimi 任务设计

### Task W2-1：部门级扫描与分类（批量）

每个 Kimi 任务负责 3-5 个部门目录，产出结构化报告。

**任务模板**：

```
你的任务是扫描以下目录中的所有 .md 文件，按照知识库入库标准进行筛选和分类。

工作目录：C:\Users\Administrator\Documents\code\kb-pipeline\ws2-website-scrape\scraped-pages\{部门名}\

筛选标准（必须全部满足）：
1. 自包含：不读其他文档也能理解
2. 可操作：至少含一个联系方式、操作步骤、时间地点、具体数值
3. SDFMU 专属：不是通用常识
4. 非过期：不含已过期的时效性通知
5. 非纯新闻：不是纯事件报道（除非含可复用信息）

对每个文件，输出一行：
文件名 | 保留/丢弃 | 分类(C01-C12) | 信息摘要(一句话) | 质量(高/中/低)

最后统计：保留 X 个，丢弃 Y 个，各分类数量。

将结果写入：C:\Users\Administrator\Documents\code\kb-pipeline\ws2-website-scrape\kimi-reports\scan-{部门简称}.md
```

### Task W2-2：内容提取与 KB 草稿生成

对 W2-1 标记为"保留"的页面，按部门合并生成 KB 文档草稿。

**任务模板**：

```
你的任务是将以下文件合并为一个符合 KB-SPEC V2 规范的知识库文档。

输入文件列表：（从 W2-1 报告中提取的保留文件清单）

输出规范：
- 必须包含 YAML frontmatter（doc_id, title, category, tags, sources, campus, last_verified）
- 每个知识点用 ## 二级标题
- 每个段落 50-500 字，自包含
- 联系方式、办事流程、政策要点必须保留具体信息
- 去除导航菜单残留、页头页尾、无意义标记

参考模板：读取 C:\Users\Administrator\Documents\code\kb-pipeline\KB-TEMPLATE.md

输出到：C:\Users\Administrator\Documents\code\kb-pipeline\04-output\from-website\{分类编号}-{序号}-{描述}.md
```

### 任务分批方案

按优先级分三批：

**第一批（高优先，与学生日常最相关）**：
- 后勤管理部、计划财务部、信息门户、学生工作部
- 预计 4 个 Kimi 任务，产出 ~4 个 KB 文档

**第二批（中优先，职能部门）**：
- 研究生院、研究生招生、团委、科研部、安全保卫部、对外合作交流部
- 预计 3 个 Kimi 任务，产出 ~6 个 KB 文档

**第三批（院系介绍）**：
- 17 个学院目录，每 3-4 个学院一个 Kimi 任务
- 预计 5 个 Kimi 任务，产出 ~17 个 KB 文档
