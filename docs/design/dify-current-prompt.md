## 1. Chatflow 总览

```
[用户输入]
  ↓
[开始] —— sys.query
  ↓
[意图分类] (Question Classifier / qwen-plus)
  ├─ greeting   → [问候回复] (固定文本) → 输出
  ├─ chitchat   → [闲聊LLM] (qwen-plus) → [闲聊输出] → 输出
  ├─ kb_query   → [知识检索] (global-kb) → [RAG 回答] (qwen-plus) → [知识回答输出] → 输出
  └─ transfer   → [转人工回复] (固定文本) → 输出
```

### 分支说明

| 分支 | 触发条件 | 终点 |
|------|---------|------|
| greeting | 问候语（你好、嗨、早上好、在吗 等） | 固定文本问候回复 |
| chitchat | 闲聊（谢谢、再见、你是谁 等非校园事务） | 闲聊 LLM 生成回复 |
| kb_query | 校园事务咨询（规则、流程、时间、地点） | RAG 检索 + LLM 生成回复 |
| transfer | 明确要求转人工（找老师、人工客服 等） | 固定文本转人工提示 |

## 4. 观察与备注

### 4.1 Prompt 完整度评估（对照 R06-3 基线）

| 维度 | R06-3 基线要求 | 当前现状 | 差异 |
|------|---------------|---------|------|
| 身份声明 | 明确"医小管"身份 | ✅ 已声明 | 无差异 |
| 回答风格 | 温和、专业、简洁、不装可爱 | ⚠️ 基本符合，但较简略 | 缺少具体风格约束（如不滥用 emoji） |
| 边界声明 | 明确声明不答天气/外卖/法律/医疗诊断 | ❌ 未声明 | **显著缺失** |
| 闲聊引导 | 礼貌 1 句 + 引导回正事 | ⚠️ "适时引导"较模糊 | 可强化 |
| 敏感问题 | 心理/医疗/法律强烈引导专业渠道 | ❌ 未声明 | **显著缺失** |
| 学院上下文 | 注入 college_name / campus / class_id | ❌ 未注入 | 等待 R06-4A 落地 |
| 防编造 | 不编造政策、电话、地址、URL | ⚠️ 仅提到不编造 URL/电话 | 可强化（缺地址、政策） |

### 4.2 参数配置观察

- **温度**：RAG 回答节点为 `0.7`，R06-1' 建议 RAG 场景使用 `0.3`（求稳）。当前温度偏高，可能导致回答一致性下降。
- **max_tokens**：所有 LLM 节点均未设置，使用模型默认值。
- **top_p**：所有 LLM 节点均未设置。
- **意图分类温度 `0.1`**：合理，符合求稳要求。

### 4.3 数据一致性异常

- `docs/design/dify-chatflow-design.md`（2026-04-14）记录：
  - "Top K：3" → 实际为 **4**
  - "Score 阈值：0.5（未启用）" → 实际**未设置**
  - "旧 Dataset ID: ... (global-kb, 432 docs)" → PROJECT-SECRETS 记录为 731 条
- 建议：更新 `dify-chatflow-design.md` 以反映实际配置。

### 4.4 可能风险

1. **边界模糊**：当前 prompt 未明确禁止医疗诊断、法律咨询、时政评论等，比赛演示时容易被"调戏"暴露弱点。
2. **温度偏高**：RAG 节点 `0.7` 在需要精确流程/政策回答的场景下可能产生不一致输出。
3. **草稿 Dataset 未发布**：草稿版指向的新 Dataset（`4db0c819-...`）尚未发布，如 TX 在 Dify UI 中误点"发布"，gateway 仍调用旧 Dataset（`ec072e85-...`），两者可能不同步。
4. **缺少 max_tokens**：长回答可能超出预期长度，增加成本和延迟。
