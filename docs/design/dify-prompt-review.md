## 1. 现状摘要

Dify Chatflow 结构：**意图分类（4 路）→ 各分支回复**。共 **3 个 LLM 节点 + 2 个固定文本节点**：

| 节点 | 类型 | 模型 | 温度 | system prompt 摘要 |
|------|------|------|------|-------------------|
| 意图分类 | Question Classifier | qwen-plus | 0.1 | "你是一个意图分类器…greeting/chitchat/kb_query/transfer" |
| 问候回复 | 固定文本 | — | — | "你好！我是医小管 🏥 …" |
| 闲聊 LLM | LLM | qwen-plus | 0.7 | "你是「医小管」…保持简短（1-2 句话）…不要编造学校相关信息" |
| RAG 回答 | LLM | qwen-plus | **0.7** | "你是「医小管」…基于以下参考资料回答，不编造…严禁编造 URL 链接或电话号码…参考资料：{{#context#}}" |
| 转人工回复 | 固定文本 | — | — | "我已收到你的转人工请求…" |

**user message 模板**（所有 LLM 节点）：`{{#sys.query#}}`
**使用变量**：仅 `{{#context#}}`、`{{#sys.query#}}`；**没有任何 `{{#inputs.xxx#}}` 变量**。

详见 `docs/design/dify-current-prompt.md` § 2.1 – § 2.6。

## 2. 要素覆盖评估（对照 R06-3 基线）

| 要素 | R06-3 基线要求 | 现状满足程度 | 证据（摘录） | 缺口 |
|------|---------------|------------|------------|------|
| 人设 | 明确"医小管"身份 | ✅ 有 | 所有 LLM 节点都写了"你是「医小管」" | 无 |
| 回答风格 | 温和、专业、简洁、口语不失规范 | ⚠️ 部分 | "友善自然"、"口语化但不失规范"、"适当鼓励" | 缺"不滥用 emoji"/"不装可爱" |
| 能力边界 | 明确拒答医疗诊断 / 法律 / 外卖 / 天气 / 政策咨询等超纲域 | ❌ 无 | prompt 中**完全无**边界声明 | **严重缺口**；比赛演示易被调戏 |
| RAG 引用格式 | 引用 `{{#context#}}` 时如何标注来源 | ⚠️ 部分 | "基于参考资料回答，不编造"、"严禁编造 URL 链接或电话号码" | 没要求"显式标注 KB 条目来源"，学生看不到引用依据 |
| 拒答策略（无证据） | "资料不足时说明 + 建议转人工/辅导员" | ✅ 有 | "如果参考资料信息不完整，如实说明已知部分，并建议咨询辅导员" | 缺口小 |
| 转人工触发 | 明确要求转人工 → 正确引导 | ✅ 有 | 独立 transfer 分支 + 固定文本 | 无 |
| 防编造 | 不编造政策、电话、地址、URL | ⚠️ 部分 | 仅列 URL 和电话 | 缺"地址、时间、政策条款" |
| 学生上下文注入 | 注入 `college_name` / `campus` / `class_id` | ❌ 无 | 所有 LLM 节点 variables 中**无** `inputs.*` | 等 R06-4A 落地；**不阻塞本次审阅** |
| 参数合理性 | RAG 温度 ≤ 0.3 求稳 | ❌ | **RAG 回答节点温度 = 0.7** | 需降至 0.3 |
| 参数合理性 | max_tokens 有限制 | ❌ | 所有节点 max_tokens 未设置 | 非阻塞，建议设 1500 |

## 3. 与 R06-4 的字段名一致性检查

**结论**：不冲突，但需要"同时改"。

| 维度 | 结论 |
|------|------|
| 现状 prompt 是否使用旧字段名（如 `college_id` / `student_name`） | **否**，现状**完全没使用**任何 `inputs.*` 变量 |
| R06-4A 引入新字段（`college_name` / `campus` / `class_id`）后 | 不会和旧 prompt 冲突（因为旧 prompt 根本不引用 inputs） |
| 本审阅对 R06-4A 的影响 | R06-4A 可以**独立先改 gateway**，不阻塞 |
| 本审阅对 R06-4B 的影响 | R06-4B 是"新增注入"，必须在 Chatflow 各 LLM 节点的 system prompt 里**加一段**"学生上下文"块，引用 `{{#inputs.college_name#}}` 等 |
| 执行顺序建议 | R06-4A → R06-4B → R06-3c（**合并或分开均可**；推荐合并为一次 Dify UI 操作，见第 5 章） |

## 4. 审阅结论

### 分级：**B. 局部补强**

### 理由
- **人设 / 拒答策略 / 转人工触发 / 防编造**：现状已覆盖（或仅需轻微加强）
- **能力边界声明缺失**：严重缺口，比赛演示易被"你能帮我点外卖吗？"、"这个病吃什么药？"、"XX 案怎么判？"这类问题暴露弱点
- **RAG 温度 0.7 → 0.3**：成本和一致性双赢
- **意图分类 qwen-plus → qwen-turbo**：纯意图判断不需要 qwen-plus，降级可显著省成本（属 R06-1' 范畴，本审阅一并建议）
- **学生上下文变量注入**：是 R06-4B 的职责，但**强烈建议与本次补强合并成一次 UI 操作**，避免反复改 Chatflow

### 对后续任务的影响

| 任务 | 是否受阻 | 说明 |
|------|---------|------|
| R06-4A（gateway 代码） | ❌ 不受阻 | 本次 prompt 没用旧字段名，gateway 改完即可跑 |
| R06-4B（注入学生上下文） | ⚠️ **合并做** | 和 R06-3c 合并为一次 UI 操作，减少发布次数 |
| batch-4 冒烟测试 | ❌ 不受阻 | 补强 prompt 不影响状态机、WS、RAG 检索逻辑 |

## 5. 补强动作（合并 R06-3c + R06-4B）

**建议产出**：`.tasks/r06-3c-exec-prompt-patch.md`，由 TX 在 Dify UI 一次性贴入新版 prompt。

### 5.1 RAG 回答节点（改动范围最大）

**动作 1**：温度 `0.7` → **`0.3`**
**动作 2**：`max_tokens` 未设 → **`1500`**
**动作 3**：system prompt 整段替换为：

```text
你是「医小管」，山东第一医科大学校园智能服务助手。

【身份与风格】
- 友善、专业、简洁；口语化但不失规范
- 可以在回答末尾适当鼓励或关心学生
- 不滥用 emoji；不装可爱；不卖萌
- 单次回复控制在 3-6 句话，长流程用编号步骤

【学生上下文】
当前学生：{{#inputs.college_name#}}{{#inputs.campus#}}{{#inputs.class_id#}}
若上述字段为空，按"通用"处理；若与问题域无关，忽略。

【能力边界 — 我能做什么】
- 校园规则、流程、办事指南、时间、地点、联系方式
- 学业、奖助学金、图书馆、医疗、心理、国际交流等校园事务
- 不知道的事情诚实说"我暂时没有这方面资料"

【能力边界 — 我不能做什么】
- 医疗诊断 / 用药建议 → 引导至校医院或正规医院
- 心理危机干预 → 引导至心理中心 + 提醒 24 小时热线
- 法律咨询 / 案件判决 → 告知不提供，建议咨询专业律师
- 天气、外卖、导航、娱乐闲聊 → 礼貌说"这不是我的专长"
- 时政评论、宗教讨论、他人隐私 → 拒绝

【回答规范】
- 严格基于下方"参考资料"回答，不编造未出现的信息
- 严禁编造 URL、电话、地址、时间、政策条款、部门名称
- 参考资料信息不完整时，如实说明已知部分，建议"可以咨询辅导员或相应部门"
- 引用关键流程 / 表单 / 条款时，在该句末尾注明来源，如"（见《学生手册 第三章》）"
- 若学生追问详细流程但资料中仅有概述，主动建议转人工

参考资料：
{{#context#}}
```

### 5.2 闲聊 LLM 节点（小改）

**动作 1**：温度维持 **`0.7`**（合理）
**动作 2**：system prompt 末尾追加 2 行，引导回正事：

```text
（保留原有内容，末尾追加：）

【边界】
- 不讨论天气、外卖、娱乐、时政、医疗诊断
- 学生若问非校园事务，礼貌回复 1 句 + 引导"校园里有什么可以帮你？"
```

### 5.3 意图分类节点（可选降级）

**动作**：模型 `qwen-plus` → **`qwen-turbo`**（属 R06-1' 范围）
**风险**：极低，意图分类不需要 qwen-plus 的复杂推理
**建议**：在同一次 UI 会话里顺手改，省去下次登录
