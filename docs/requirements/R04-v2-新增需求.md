# v2 开发过程中新增需求

> 来源：v2 开发过程中与 TX 讨论产生的需求变更和新增功能
> 状态：**持续更新中**
> 说明：本文档记录从 v1→v2 架构迁移过程中新发现的需求，以及对 v1 需求的修正。

## 一、架构变更导致的需求变化

### v1 → v2 技术栈变更

| 组件 | v1 | v2 | 影响 |
|------|----|----|------|
| 主后端 | Java Spring Boot（若依） | Python FastAPI | 原 R03 中 Java 相关决策不再适用 |
| AI 引擎 | 独立 Python AI Service + ChromaDB | Dify (self-hosted) Chatflow | 意图识别、RAG 全部由 Dify 承担 |
| 向量库 | ChromaDB | Dify 内置（通义千问 embedding） | 不再单独管理向量库 |
| 实时通信 | Spring WebSocket | FastAPI WebSocket | 协议兼容，实现方式变化 |

### R01 需求在 v2 中的实现状态

| 原需求 | v2 状态 | 说明 |
|--------|---------|------|
| 智能问答（RAG） | ✅ 已实现 | 通过 Dify Chatflow kb_query 分支 |
| 教师实时插入 | ✅ 已实现 | WebSocket + 状态机（S2 交付） |
| 空教室申请 | ❌ 已放弃 | R03 中确认改为链接跳转 |
| AI 人设定制 | 待做 | Dify 侧可通过 system prompt 实现 |
| 知识库审核流 | 简化 | v2 一级审核，通过 Dify Dataset API 管理 |
| 通知推送 | 待做 | v1 后端已完成但前端未接，v2 需重新实现 |

## 二、v2 新增需求

### N1：Dify Chatflow 分支优化

**当前 4 分支**：
1. 闲聊/greeting → 闲聊 LLM
2. kb_query → 知识检索 → RAG → 输出
3. transfer → 转人工
4. （其他意图兜底）

**已确认不加新分支**，但需要微调：
- RAG 检索后的 LLM prompt 加入用户上下文（college_name, campus）
- 意图分类的 inputs 增加用户属性字段

### N2：KB 从 433 条重建到 1000+

**背景**：旧 433 条 KB 质量存疑，决定从头构建。

**数据来源**：
- W1：原始材料（学生手册等）→ 240 个 markdown
- W2：官网抓取 → 1999 个 markdown
- W3：公众号文章 → 采集中

**输出规范**：见 `kb-pipeline/KB-SPEC.md`

**入库策略**：
- 新建 Dify dataset `global-kb-v2`（旧的保留对比）
- 按主题/部门合并为 50-80 个大文档
- 12 个互斥分类体系
- 通过 API create-by-text 上传

### N3：.env 配置修正

当前 `services/gateway/.env` 中 `dify_api_url=http://localhost:3000/v1`
应改为 `http://192.168.100.165:3000/v1`（Dify 部署在 165 上）。

> 注意：此修改仅影响本地开发环境，生产部署时需再次确认。
