# Dify 知识库隔离评测与上线判断

评测日期：2026-08-09
评测原则：不调用线上 Dify Dataset/Chat API，不写 PostgreSQL、Weaviate、工作流或应用配置；只将 10 个 Dataset 的 PostgreSQL/Weaviate 状态只读导出到本机临时目录后评测。

## 结论

目前没有一个现存版本同时满足“广域覆盖、检索效果、索引完整、来源治理”四项要求，**不建议直接切换或作为正式生产版本发布**。

- 广域语义检索最好的是当前主库 `医小管知识库`：27 条统一题集的本地中文向量 Hit@1 为 **81.5%**，Hit@3 为 **88.9%**。
- 广域索引最稳的是旧 `global-kb`：精确覆盖 **99.4%**、内容覆盖 100%、活动文档下无陈旧向量；但内容较旧、治理元数据不足，语义 Hit@1/Hit@3 为 77.8%/85.2%。
- 学业影响检索最好的是 `医小管-学业影响精准知识库-v2-中文标题-20260804`：15 条专项题 Hit@1/Hit@3 均为 **100%**；但精确索引覆盖只有 **87.1%**。
- 奖学金专项中，主库为 90%/100%，`scholarship-precision-shadow-v2-20260803` 为 80%/100%。精准库的价值在于来源、时效和权威级别元数据 100% 覆盖，应作为受控证据层，而不是替代主库。

推荐目标版本不是现有某个库的原样切换，而是：**V2 主库内容 + 中文标题专项卡 + 修复后的全量干净重建 + 意图路由**。

## 测试范围与口径

只读快照包含：

- 10 个 Dataset；
- 1,763 个 Dify Document；
- 4,063 个 PostgreSQL Segment；
- 4,192 个 Weaviate Object；
- 62 条人工金标查询：27 条广域、20 条奖学金、15 条学业影响；
- 字符 n-gram BM25 和本地 `BAAI/bge-small-zh-v1.5` 两套检索器；
- 4 个索引身份/快照指标回归测试。

本地向量模型不等同于线上 `text-embedding-v4 + qwen3-rerank`。本报告的语义成绩用于同一快照、同一模型下的版本横向比较，不作为线上端到端成绩冒充。按用户要求，本轮没有调用真实 Chat API，因此没有新增线上答案日志、模型成本或写操作。

主库 1,718 个活动 Segment 中：

- 1,579 个能按当前 `index_node_id` 精确找到向量，缺 139 个；
- 另有 16 个缺失 Segment 的相同正文仍被其他可搜索对象表示；
- 仍有 **123 个活动 Segment 没有等价的可搜索正文**；
- 32 个旧对象仍挂在活动 Document 下，会参与检索；
- 5 个活动文档仍包含明确“待确认/待补充”段落；
- 780 个活动文档中只有 38 个包含统一的 `source_url + effective_status + authority_level` 治理卡字段。该数字只衡量标准化显式字段，不代表其余文档完全没有内部源文件线索。

主库的广域语义失分集中在 5 类：学生报销、VPN、外国留学生在校服务、研究生调剂排序、学院联系方式排序。其中前三类在本地有补缺草稿，但草稿包含 `[待核实]`、推测电话/地点或未确认流程，不能直接入库。

## 已确认的技术根因与本地修正

Dify 1.13.3 当前 Weaviate 适配器按 Segment 正文生成 UUID5：相同正文会共享对象 ID并覆盖元数据；删除时却把 PostgreSQL 的 `index_node_id` 当作 Weaviate 对象 ID。两条身份规则不一致，导致：

- 相同正文发生对象覆盖；
- `delete_by_ids()` 返回成功但没有删除目标对象；
- 重建/更新后留下陈旧对象；
- 被覆盖对象可能指向停用 Document，活动文档过滤后正文不可检索。

本地补丁改为优先使用 `metadata.doc_id`（即 `index_node_id`）作为 Weaviate 对象 ID。快照中全部 4,063 个 Segment 的 `index_node_id` 均是合法、同 Dataset 内唯一的 UUID；模拟重建可达到 **100% ID 唯一、100% 精确映射**。4 个回归测试已通过，覆盖重复正文、删除 ID 一致性、旧数据回退和快照指标计算。

需要注意：补丁本身不会修复既有 Collection。最终处理必须是“新 Collection 全量重建 → 校验 → 原子切换”，不能只在旧 Collection 上继续补写。

## 最好的已验证结果与可达目标

### 当前已验证上限

- 广域：主库本地语义 Hit@1 **81.5%**、Hit@3 **88.9%**；即使按 PostgreSQL 活动 Segment 模拟完整索引，这 27 条仍是 81.5%/88.9%，说明仅重建索引不能解决内容和排序问题。
- 奖学金：主库 90%/100%；精准库 80%/100%。
- 学业影响：中文标题 v2 100%/100%。
- 历史端到端报告的 27 条结果是可用回答 92.6%、精准回答 74.1%。历史另有“37 条 Top-1 97.3%”的汇总结论，但原始题集和结果文件不在当前仓库，不能独立复现，故不作为验收成绩。

### 修复后应达到的上线门槛

以下是验收目标，不是已经实现的成绩：

| 指标 | 上线门槛 |
|---|---:|
| Segment ↔ Vector 精确覆盖 | 100% |
| 内容可搜索覆盖 | 100% |
| 活动文档下陈旧向量 | 0 |
| 重复正文导致对象覆盖 | 0 |
| 高风险卡片来源 URL / 权威级别 / 时效状态 | 100% |
| 含待核实占位符的活动文档 | 0 |
| 至少 100 条盲测的 Hit@1 | ≥ 90% |
| 至少 100 条盲测的 Hit@3 | ≥ 96% |
| 端到端可用回答率 | ≥ 95% |
| 端到端精准回答率 | ≥ 85% |
| 越权、跨学院、跨学年误答 | 0 个 P0/P1 |

补齐并核实学生报销、VPN、外国留学生在校服务三类资料，再给调剂和学院联系方式增加中文查询别名后，广域 Top@K 有希望进入上述目标区间；在真实 Dify rerank 下达到多少，必须用新的盲测集实测，不能由本地模型直接保证。

## 是否具备真实上线能力

**当前结论：不具备直接正式上线能力；具备修复后进入影子流量/小规模灰度的内容基础。**

正式上线前至少完成：

1. 合入并审核 Weaviate 身份补丁，建立新的空 Collection；
2. 对主库和两个专项库限速全量重建，处理通义 embedding 429，直到精确覆盖 100%；
3. 校验新 Collection 无陈旧对象后原子切换，旧 Collection 保留为短期回滚；
4. 不导入现有 7 篇补缺草稿，先让业务方逐项核实来源、电话、地点、费用和办理时间；
5. 修复未消费的 `trigger_refresh_publisher` 队列并验证备份/恢复，避免 Redis 持续增长；
6. 使用与线上完全相同的 embedding、rerank、提示词和回答模型，跑不少于 100 条盲测、歧义题、跨学院/跨学年隔离题和无答案题；
7. 达标后先影子流量，再 5% 灰度，观察无结果率、低分率、引用正确率和 P95 延时后扩量。
