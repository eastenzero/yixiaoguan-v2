# ISSUE-002 知识问答质量判定过宽

## 现象

部分低相关来源的回答被系统判定为“已回答”。AI 会基于弱来源生成一段看似完整的答案，但来源并不可靠，导致问题不会进入待补队列。

## 证据

2026-06-20 学生端样本：

- `宿舍电费怎么交？` 命中 `电费缴纳指南`，RAG 分数 `0.9008`，质量较好。
- `奖学金申请流程怎么走？` 第一来源为 `对外合作交流部 — 出国留学流程与咨询`，RAG 分数 `0.1985`，但仍标记为已回答。
- `黄河图书馆开放时间是什么？` 命中 `口腔医学院 — 黄河图书馆使用指南`，RAG 分数 `0.8957`，质量较好。
- `校园卡丢了怎么办？` 命中 `校园卡实体卡挂失与补卡流程`，RAG 分数 `0.8198`，质量较好。
- `怎么联系辅导员？` 第一来源为 `学生工作部 — 春季学期返校指南`，RAG 分数 `0.1865`，但仍标记为已回答。

代码中 `judge_is_answered()` 的逻辑是：

- 没有 RAG 分数：未回答
- 分数 >= `0.3`：已回答
- 分数 < `0.3`：只要回答长度 >= 20，也算已回答

## 影响

- 低质量回答不会进入运营闭环。
- 教师端看不到真正需要补充的问题。
- 学生可能收到“像真的但依据很弱”的答案。

## 涉及区域

- `services/gateway/app/services/analytics.py`
- `services/gateway/app/routers/chat.py`
- Dify workflow / RAG 配置

## 建议修复方向

- 不再用“回答长度”兜底判定已回答。
- 引入低分阈值、来源相关性、拒答/泛答检测。
- 对低分但长回答标记为 `needs_review` 或进入“低置信问答”队列。
- 前端显示来源置信度或低置信提醒。
