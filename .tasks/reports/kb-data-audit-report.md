## 四、V1 独有内容分析

### 4.1 两个版本的数据来源对比

| 维度 | V1 | V2 |
|------|----|----|
| 数据源 | 学生手册 + 少量公众号 | W1(原始材料含学生手册) + W2(官网 92 份) + W3(公众号 645 篇) |
| 来源广度 | 窄，单一 | 宽，三路并行 |
| 分类体系 | 31 个（重叠严重） | 12 个（互斥分明） |
| doc_id | 无统一编号 | KB-V2-C{编号}-{序号} |
| campus 标记 | "通用"/"济南校区"等不规范 | 三值归一：通用/济南校区/泰安校区 |
| 数据溯源 | 仅 source 行号 | sources 数组（含 type + path） |
| 状态管理 | draft/active/archived 混合 | 无 status 字段（由 Dify 侧管理） |

### 4.2 V1 数据质量评估

**优势**：
- KB-0XXX batch（22 篇）来自学生手册精加工，内容密度高，步骤详细
- 部分条目如"电费缴纳指南"、"校园卡办理与使用"有清晰的操作步骤
- 使用 `# ## ###` 多级标题组织，便于人工阅读

**劣势**：
- **410/433 = 94.7% 处于 draft/草稿/needs_review 状态**，未经过审核验收
- 分类重叠严重（如"毕业与就业"与"就业与毕业"并存）
- 无 doc_id 体系，无法与 Dify/PG 数据库关联
- frontmatter 缺失规范字段（sources、last_verified 等）
- 正文格式不均：部分使用 QA 模板（问题概述/标准答复），部分使用指南格式
- 内容时效未标注（大量 2024-2025 赛季内容，可能已过期）

### 4.3 是否有 V1 独有、V2 未覆盖的内容？

根据数据源覆盖对比，**V2 的数据源是 V1 的超集**：

| 数据覆盖 | V1 | V2 (W1+W2+W3) |
|---------|----|---------------|
| 学生手册 | ✅ 核心来源 | ✅ 已纳入 (W1, 164 篇) |
| 官网部门信息 | ❌ | ✅ W2 全量抓取 (93 篇, 含 17 学院+31 部门) |
| 公众号内容 | 极少 | ✅ W3 全量 (703 篇, 16 个公众号) |
| 规章制度原文 | ❌ | ✅ MinerU (399KB full.md) |
| 图文教程 | ❌ | ✅ 12 原子 + 4 组合教程 |

**结论**：从数据来源和条目数量两个维度看，V2 已全面覆盖 V1 的内容域。V1 不存在 V2 完全未涉足的知识领域。

**但需注意**：
1. V1 部分条目的"步骤编排"更细致（如"电费缴纳指南"含 3 种缴费渠道的详细对比），V2 同类条目可能更偏"部门职责概述"而非"操作步骤"
2. V1 有 208 篇标记为 `draft` 的条目（KB-2026 batch），这些条目可能包含 V2 没有的具体问答对，建议将这些草稿纳入 V2 的质量审计范围

## 六、格式规范对比

### 6.1 V1 模板 (knowledge-entry-template.md)

```yaml
title, category, audience, summary, answer,
source_files, source_type, effective_date,
updated_at, status, reviewer, tags
```
- 字段定义偏"人工 QA 编辑"场景
- 缺少 doc_id、sources 结构化溯源
- `status: draft | active` 在 V2 中被移除（Dify 侧管理）

### 6.2 V2 规范 (KB-SPEC v2.0)

```yaml
doc_id, title, category, tags, sources[{type, path}],
campus, last_verified
```
- 强约束 doc_id 体系：`KB-V2-{分类编号}-{三位序号}`
- sources 数组支持多源标注
- campus 三值归一
- 正文：`##` 标题 = Dify 切分点，`---` 分隔知识点
- 50-500 字 / 段

### 6.3 兼容性评估

V1 条目若要迁移到 V2 规范，需要进行：
1. **分类映射**（31→12）— 可自动化
2. **doc_id 生成** — 可自动化
3. **frontmatter 重构**（添加 sources, last_verified 等）— 需人工审核
4. **campus 标准化**（"济南+泰安双校区"→"通用"等）— 可自动化
5. **正文重构**（`#`→`##`，添加 `---` 分隔符）— 需 AI 辅助
6. **状态清理**（draft/active → 只保留经过核实的内容）— 人工决策

### 7.2 推荐策略：增量补充，而非全量融合

**不建议将 V1 全量导入 V2**，原因：
1. V1 的 208 篇 draft 未经验收，混入会降低整体质量
2. V2 已在所有分类上超越 V1 体量
3. V1 格式与 V2 不兼容，全量迁移成本高

**建议操作**：
1. **挑选 V1 中的高价值条目**（状态=active、内容为步骤指南型），抽取后人工审核
2. **将审核通过的条目按 V2 规范重新格式化**，作为 V2 的增量补充
3. **V1 draft 条目作为"待挖掘素材"**，在 V2 检索测试中发现缺口时定向提取
4. **V1 first-batch-drafts 目录可归档删除**（与 entries/ 根目录重复）

### 7.3 具体融合优先级

| 优先级 | V1 条目特征 | 建议处理 |
|--------|-----------|---------|
| 🔴 高 | 状态=active、含操作步骤 + 联系方式 | 重新格式化为 V2 → 入库 V2 |
| 🟡 中 | 状态=draft、主题在 V2 中无对应条目 | AI 审核真实性 → 确认后入库 |
| 🟢 低 | 状态=draft、主题已在 V2 中存在等量/更优内容 | 不做处理，按需抽检 |
| ⚪ 跳过 | 状态=archived / 纯通知 / 已过期 | 归档 |

### 7.4 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| V1 draft 内容含幻觉 | 错误信息入库影响回答准确性 | 仅导入 status=active 条目，且需人工审核 |
| V1 分类映射错误 | 知识归类不正确影响检索 | 使用 KB-SPEC 附录 C 映射表自动化执行 |
| V1 内容时效过期 | 过时信息误导学生 | 检查 last_verified 等效字段，丢弃超过 1 年的条目 |
| Dify Dataset 混合导致回归 | 检索准确率下降 | 小批量 A/B 测试后再全量导入 |
