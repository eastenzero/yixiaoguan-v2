# 上线前预期管理与轻量功能填充方案

## 背景

当前版本的核心定位是“校园事务 AI 咨询入口 + 人工兜底 + 常用链接导航”。这个方向是成立的，且核心链路已经可用：

- 学生可以通过 AI 问校园事务、流程、政策、入口。
- AI 无法回答时可以转人工。
- 辅导员可以接单、回复、解决。
- 教师端知识库可以围绕未回答问题补充内容。

但 UI 设计阶段为了优先对齐完整组件效果，放入了大量“看起来已经上线”的服务入口。实际功能尚未对接学校系统，导致用户看到的是完整办事平台，点击后却没有完整办事能力。这个落差会明显影响信任感。

本方案目标不是删空页面，也不是临时硬接学校系统，而是把这些入口改造成围绕核心能力的轻量功能，让用户预期从“这里能直接办事”调整为“这里能查流程、找入口、问老师、获得下一步指引”。

## 核心原则

1. 不伪装成完整办事系统  
   未对接的功能不能表现得像“已经可在线办理”。

2. 不删除页面丰富度  
   保留服务卡片和布局，但改变交互语义。

3. 所有占位入口必须有结果  
   点击后至少出现说明、跳转 AI 咨询或跳转外部系统，不能无反馈。

4. 把用户导回核心能力  
   未上线功能优先转为“问医小管”“查看办理流程”“联系老师”。

5. 清晰标记能力状态  
   用统一标签区分：`AI 可问`、`外部系统`、`建设中`。

## 当前主要问题

### 学生端

- 首页和事务导办入口很多，视觉上像完整服务大厅。
- 部分入口点击无反馈，例如空教室申请、接诉即办、班车查询、我的申请、消息通知、意见反馈等。
- 当前占位/建设中提示主要使用 `uni.showModal` / `uni.showToast` 原生弹层，和页面视觉体系割裂，显得像临时处理或系统错误。
- 部分入口直接打开外部网站，需要在入口视觉上标明“外部系统”，但不额外增加确认步骤。
- “一站式办事入口”“便捷办事 · 智慧生活”等文案容易让用户误以为可以直接完成办理。
- 个人页中问答历史、我的申请、通知、设置、反馈等数据看起来真实，但部分是占位或静态数据。

### 教师端

- 工作台首屏四个快捷入口“新建知识 / 发布通知 / 数据报告 / 系统设置”看起来是核心工作能力，但点击没有明显反馈。
- 教师端建设中提示同样使用原生 `uni.showModal`，视觉上不像产品内组件。
- 教师端工作台待处理数量不会实时刷新，进入“学生提问”列表后才能看到新增待处理。
- 知识库“去补充”是有价值入口，但点击区域/滚动区域存在命中不稳定风险。

## 上线前低开发量改造方案

### 1. 未对接服务入口改为“AI 代办咨询入口”

适用入口：

- 空教室申请
- 我的申请
- 接诉即办
- 校园网
- 校医院
- 班车查询
- 学生课表
- 成绩查询
- 个人日程
- 消息通知
- 意见反馈
- 帮助中心

点击行为：

- 不再假装进入完整功能。
- 跳转到智能问答页。
- 自动带入预设问题，优先直接发送。

建议预设问题：

| 入口 | 预设问题 |
|---|---|
| 空教室申请 | 我想申请空教室，办理流程是什么？ |
| 我的申请 | 我想查看或跟进自己的校园事务申请，应该去哪里？ |
| 接诉即办 | 我想反馈校园问题或投诉建议，应该怎么提交？ |
| 校园网 | 校园网怎么开通、登录和报修？ |
| 校医院 | 校医院就诊流程和开放时间是什么？ |
| 班车查询 | 班车时刻表在哪里查询？ |
| 学生课表 | 学生课表在哪里查看？ |
| 成绩查询 | 成绩查询入口在哪里？ |
| 个人日程 | 学校重要日程在哪里查看？ |
| 消息通知 | 我在哪里查看学校通知和老师回复？ |
| 意见反馈 | 我想反馈医小管使用问题，应该怎么说？ |
| 帮助中心 | 医小管可以帮我做什么？ |

验收标准：

- 每个入口点击后有明确页面变化。
- 用户能看到 AI 正在回答或输入框内已有对应问题。
- 不出现无反馈点击。

### 2. 给入口增加能力标签

建议标签：

- `AI 可问`：点击后进入 AI 咨询。
- `外部系统`：点击后打开学校已有系统或官网页面。
- `建设中`：确实没有替代路径的功能。

推荐分类：

| 入口 | 标签 | 行为 |
|---|---|---|
| AI 智能助手 | 已上线 / 可用 | 进入智能问答 |
| 对话历史 | 已上线 / 可用 | 进入历史对话 |
| 教务管理系统 | 外部系统 | 直接打开教务部网站 |
| 图书馆 | 外部系统 | 直接打开图书馆网站 |
| 学生邮箱 | 外部系统 | 直接打开邮件系统 |
| 学校官网 | 外部系统 | 直接打开官网 |
| 网上报修 | 外部系统 或 AI 可问 | 优先外链；无稳定入口时转 AI 咨询 |
| 空教室申请 | AI 可问 | 问流程 |
| 接诉即办 | AI 可问 | 问提交方式 |
| 班车查询 | AI 可问 | 问查询入口 |
| 我的申请 | 建设中 | 弹说明 + 引导问 AI |
| 个人日程 | 建设中 | 弹说明 + 引导问 AI |

验收标准：

- 首屏用户可以区分哪些能直接用，哪些是问流程，哪些尚未接入。
- 未上线入口不再和已上线入口同等视觉权重。

### 3. 统一自定义占位反馈弹层

不要继续使用原生 `uni.showModal` / `uni.showToast` 承载建设中提示。原生弹层视觉生硬，用户会感觉这是浏览器/系统层面的错误反馈，而不是产品有意设计的引导。

需要新增一个应用内自定义弹层组件，建议命名：

- 学生端：`AppActionSheet` 或 `FeatureNoticeModal`
- 教师端：可复用同名组件，保持样式一致

所有尚未上线但仍保留的入口，统一弹出应用内弹层：

```text
该功能正在接入中
你可以先让医小管帮你查询办理流程、材料和入口。
```

按钮：

- `问问医小管`
- `我知道了`

视觉要求：

- 使用产品内卡片样式，不使用浏览器/系统原生确认框。
- 标题、正文、主按钮、次按钮层级清晰。
- 可配图标：`construction`、`auto_awesome`、`open_in_new`。
- 主按钮使用品牌紫，但弹层背景保持白底或浅色，不使用大面积高饱和渐变。
- 移动端底部弹出或居中弹出均可，但必须有遮罩、圆角、舒适留白。
- 关闭后不改变当前页面状态。

外部系统入口不增加确认弹层。它们本身就是快捷入口，额外确认会降低效率。处理方式改为：

- 卡片上标注 `外部系统`。
- 搭配 `open_in_new` 图标或轻量说明。
- 点击后直接打开外部链接。
- 不弹“将打开学校外部系统”的确认框。

验收标准：

- 不再出现点击无反馈。
- 用户知道下一步可以做什么。
- 外链入口在点击前通过标签和图标建立心理预期，但不拦截跳转。
- 学生端和教师端不再出现用于占位功能的原生 `uni.showModal` / `uni.showToast`。
- 业务成功/失败类短提示可以继续使用 Toast，但建设中和 AI 引导必须使用自定义弹层。

建议接口形态：

```ts
showFeatureNotice({
  title: '该功能正在接入中',
  description: '你可以先让医小管帮你查询办理流程、材料和入口。',
  icon: 'construction',
  primaryText: '问问医小管',
  secondaryText: '我知道了',
  suggestedQuestion: '我想查看或跟进自己的校园事务申请，应该去哪里？',
})
```

外部系统入口：

```ts
openExternal(url)
```

调用前提：

- 卡片/列表项已经显示 `外部系统` 标签。
- 图标或样式能让用户理解这是外部入口。
- 不额外弹确认框。

### 4. 文案降级，避免承诺完整办事能力

建议替换：

| 当前文案 | 建议文案 |
|---|---|
| 校园服务中心 | 校园服务指南 |
| 便捷办事 · 智慧生活 | 常见事务 · 流程咨询 · 入口导航 |
| 一站式办事入口 | 不确定怎么办，先问医小管 |
| 服务大厅 | 服务指南 |
| 我的申请 | 我的咨询与进度 |

验收标准：

- 页面仍然丰富，但不再承诺“在线办完”。
- 用户预期更接近“咨询与导航”。

### 5. 首页增加“常见问题快捷问”

在学生端首页或事务导办顶部放 8-12 个快捷问题：

- 宿舍电费怎么交？
- 奖学金怎么评？
- 图书馆几点开？
- 校园网怎么连？
- 报修在哪里办？
- 成绩怎么查？
- 请假流程是什么？
- 怎么联系辅导员？
- 空教室怎么申请？
- 校医院怎么就诊？

点击行为：

- 进入智能问答页。
- 自动发送对应问题。

验收标准：

- 页面有内容填充。
- 所有入口都能产生有效回答。
- 用户更容易理解产品能力边界。

### 6. 首页增加“最近提问 / 继续咨询”

使用已有会话数据展示最近 3 条：

- 会话标题
- 状态：AI 解答中 / 老师服务中 / 已解决 / 已关闭
- 最近时间
- 点击继续

验收标准：

- 数据来自真实会话，不使用假数字。
- 点击能进入对应历史会话。
- 让首页更贴近核心能力。

### 7. 我的页静态数字改为真实或弱化

当前“问答历史 128”“我的申请 12”等数字容易被用户理解为真实数据。

建议：

- 问答历史：改为真实会话数量，或显示“查看记录”。
- 我的申请：上线前改为“老师回复 / 待处理 / 已解决”等核心链路状态。
- 学期进度、AI 助手示例：如果不是实时数据，弱化为推荐卡片，不使用具体假数据。

验收标准：

- 不出现明显假数据。
- 用户点击后能进入真实功能或明确提示。

## 教师端改造方案

### 1. 工作台首屏快捷入口调整

当前四个快捷入口：

- 新建知识
- 发布通知
- 数据报告
- 系统设置

建议调整：

| 当前入口 | 上线前处理 |
|---|---|
| 新建知识 | 改为“查看待补问题”，跳知识库高频待补 |
| 发布通知 | 加 `建设中` 标签，点击显示建设中弹层 |
| 数据报告 | 加 `建设中` 标签，点击显示建设中弹层 |
| 系统设置 | 移到“我的”页，首屏不强调 |

验收标准：

- 教师首屏优先展示真实可用能力。
- 不再让教师误以为通知、报表、设置已经可用。

### 2. 工作台待处理实时刷新

短期方案：

- 页面 `onShow` 时重新拉取待处理列表。
- 收到 WebSocket 相关事件时重新拉取待处理列表。
- 如果实时事件成本较高，至少提供明显的“刷新”按钮。

验收标准：

- 学生转人工后，教师无需进入列表即可看到待处理变化；或能通过显眼刷新按钮看到。

### 3. 知识库“去补充”交互稳定化

建议：

- 增大按钮点击区域。
- 避免被顶部栏或底部栏遮挡。
- 点击后进入补充表单或弹出补充面板。

验收标准：

- 自动化和人工点击都能稳定触发。
- 点击后可提交草稿或显示明确错误。

## 优先级建议

### P0：上线前必须修

- 所有无反馈点击改成统一反馈或跳 AI 咨询。
- 学生端服务入口增加 `AI 可问 / 外部系统 / 建设中` 标签。
- 教师端工作台四个快捷入口降级或补反馈。
- 学生当前页老师回复实时展示问题单独修复。

### P1：上线前强烈建议

- 首页增加常见问题快捷问。
- 首页增加最近提问 / 继续咨询。
- 外链入口增加 `外部系统` 标签和 `open_in_new` 图标，点击直接打开。
- 我的页假数据改为真实数据或弱化。

### P2：内测后继续优化

- 服务详情模板页。
- 教师端数据报告真实化。
- 通知发布。
- 我的申请 / 事务办理系统对接。

## 推荐落地顺序

1. 先做统一入口处理函数：
   - `openAiQuestion(question)`
   - `openExternal(url, label)`
   - `showComingSoon(featureName, suggestedQuestion?)`

2. 批量替换学生端所有服务卡片点击行为。

3. 给服务卡片加能力标签。

4. 调整学生端文案：
   - 服务大厅 -> 服务指南
   - 一站式办事入口 -> 流程咨询与入口导航

5. 调整教师端工作台快捷入口。

6. 修复学生当前页老师回复实时展示。

7. 增加最近提问 / 常见问题快捷问。

8. 跑 UI 冒烟：
   - 学生每个服务入口点击有反馈。
   - 教师每个快捷入口点击有反馈。
   - 外链有明确视觉标识，点击直接打开。
   - AI 快捷问能进入问答。

## 验收清单

- [ ] 学生端首页所有可点击卡片都有明确反馈。
- [ ] 学生端事务导办所有入口都有明确反馈。
- [ ] 学生端我的页所有入口都有明确反馈。
- [ ] 未上线功能不再表现为已上线完整办理。
- [ ] 外链入口有明确视觉标识，点击直接打开。
- [ ] AI 可问入口能自动进入问答。
- [ ] 教师端工作台快捷入口不再无反馈。
- [ ] 教师端知识库“去补充”可稳定点击。
- [ ] 学生当前页可实时看到老师回复。
- [ ] 控制台不出现新增业务错误。

## 对用户心理预期的影响评估

如果不改：

- 学生端预期差：高。页面像完整办事平台，但很多功能点不动或无法办理。
- 教师端预期差：高。首屏核心按钮点不动，会影响专业感。
- 内测解释成本：高。需要反复说明哪些功能没上线。

按本方案改造后：

- 学生端预期差：中低。用户知道当前主要是咨询、流程、入口导航。
- 教师端预期差：中低。首屏更聚焦真实可用工作。
- 页面丰富度：保留。卡片仍在，但语义更准确。
- 开发量：可控。主要是点击行为、文案、标签、统一弹层和少量真实数据展示。

## 最终建议

上线前不要删除大量组件，也不要继续保留无反馈占位。最佳策略是：

> 把“未接入的办事入口”改造成“AI 咨询入口 / 外部系统导航 / 建设中说明”，让产品从完整办事平台回到“校园事务 AI 咨询与人工兜底平台”的真实定位。

这样既能保留页面完成度，又能显著降低用户心理预期差，并且开发量远小于对接学校各业务系统。
