# 学生端到教师端的可复用路径

## 页面映射

| 已验证的学生端模式 | 教师端落点 | 迁移重点 |
| --- | --- | --- |
| 首页玻璃搜索/主入口 | `pages/dashboard/index.vue` 工作台头部与快捷操作 | 保留待处理数量和真实动作，不做装饰性搜索 |
| 最近提问卡片 | `pages/questions/index.vue` 队列 | 用状态、时间、学院/标题建立扫描层级 |
| 问答消息气泡、来源卡片 | `pages/questions/detail.vue` | 回复、转人工、来源原文和长文本在同一连续流程中 |
| 知识库更新与证据卡 | `pages/knowledge/index.vue`、`detail.vue` | 保持条目状态、审核动作和官方来源可追溯 |
| 学生端 `CustomTabBar` | 教师端 `BottomNavBar.vue` | 复用安全区、活动态和按下反馈；教师端保留四项信息架构 |
| 学生端 `AppIcon.vue` | 教师端 `components/icons/` | 保持线性图标比例，不直接把学生 CSS 图标复制进教师端 |

## 推荐改造顺序

1. 先把 `$primary`、表面层、圆角、间距和 backdrop 统一到教师端页面使用的 token。
2. 调整工作台头部、快捷操作和统计卡，确保待处理问题是视觉第一优先级。
3. 调整问题列表与详情：统一卡片容器、状态 badge、长文本折行、来源链接和回复区；不改变 API 字段。
4. 调整知识库列表/详情：把审核状态、更新时间、来源单位和操作放在稳定的栅格里；超长标题可换行。
5. 最后处理个人中心、设置和空状态，避免先做装饰页而遗漏核心处理路径。

## 不可破坏的行为契约

- 保留 `listConversations`、知识库 API、WebSocket/Centrifugo 事件和现有权限判断。
- `pending_teacher`、`teacher_serving`、`resolved`、`closed` 等状态必须继续映射到原有动作和文字。
- 回复失败、断线、无权限和空数据必须可见；不能用一个“在线”徽章掩盖真实失败。
- 用户点击列表项后应能回到原筛选条件；刷新后不丢失当前会话 ID。

## 响应式验收矩阵

- 360×800：导航标题、状态、学生问题、回复输入区均不横向溢出。
- 430×932：卡片左右留白一致，长标题和来源链接自然换行。
- 768px 以上：桌面内容可扩展，但核心队列和详情保持清晰的主次列关系。
- 键盘/输入法出现时：输入框不被底部导航或安全区遮挡。
- `prefers-reduced-motion`：页面仍有明确的选中、按下、成功和错误反馈。

## 发布和回滚

教师端上线前执行：`npm run type-check`、`npm run build:h5`、`git diff --check`。服务器上先把当前 `/var/www/yixiaoguan/teacher` 和涉及的 gateway 文件复制到带时间戳的备份目录，再替换静态文件；记录提交号、备份目录、健康检查结果和一条可直接执行的恢复命令。不要因前端视觉任务执行整仓库 `git pull`，尤其是服务器存在同事未提交后端时。
