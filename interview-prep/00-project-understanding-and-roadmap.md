# 医小管 v2 项目理解与面试准备路线图

> 面向 Java/Python 后端开发实习面试的项目全景梳理

---

## 一、项目一句话定位

> 医小管 v2 是一个基于 Dify Chatflow 的校园 AI 助手系统，采用 FastAPI 单体 + UniApp 双端架构，支持知识库问答、教师实时介入、意图识别和个性化回答，知识库覆盖 960+ 条校园服务知识。

---

## 二、项目背景与业务价值

### 2.1 业务痛点

1. **信息孤岛**：校园服务信息分散在教务系统、后勤系统、图书馆系统等多个平台
2. **查询效率低**：学生需要登录多个系统才能获取完整信息
3. **服务时间受限**：人工客服无法24小时响应
4. **知识更新滞后**：传统FAQ难以及时更新，信息准确性差

### 2.2 解决方案

1. **统一入口**：AI助手作为校园服务的统一入口
2. **智能问答**：基于RAG技术实现精准知识检索
3. **人机协作**：AI自动服务+教师实时介入的无缝切换
4. **知识迭代**：基于用户反馈持续优化知识库

### 2.3 业务价值

1. **提升效率**：7×24小时即时响应，减少学生等待时间
2. **降低成本**：AI处理80%常见问题，释放教师精力
3. **优化体验**：个性化回答，精准匹配学生需求
4. **数据驱动**：基于对话数据优化服务流程

## 四、核心业务流程

### 4.1 用户认证流程

```
学生微信登录 → 获取openid → 查询/创建用户 → 生成JWT → 返回token
```

### 4.2 对话交互流程

```
学生发送消息 → Gateway接收 → 检查会话状态
  ├─ AI服务中 → 调用Dify Chatflow → 流式返回结果
  ├─ 待教师接入 → 推送等待提示
  └─ 教师服务中 → 通过WebSocket推送给教师
```

### 4.3 知识库检索流程

```
用户查询 → 意图分类 → 知识检索 → 向量化 → 语义匹配 → 重排序 → 生成回答
```

### 4.4 教师介入流程

```
学生请求转人工 → 创建工单 → 通知教师 → 教师接单 → 会话状态变更
  → 学生消息实时推送 → 教师回复 → 学生接收 → 会话结束
```

## 六、技术深度亮点

### 6.1 异步架构设计

**核心优势**：
1. FastAPI基于asyncio实现异步处理
2. SQLAlchemy异步模式避免同步阻塞
3. SSE流式响应使用异步生成器
4. Redis异步操作提高并发性能

**面试话术**：
> "FastAPI原生支持异步，我们使用SQLAlchemy的async session操作数据库，避免了同步阻塞。在处理Dify的SSE流式响应时，使用异步生成器逐块读取并转发给前端，保证了长连接场景下的性能。"

### 6.2 状态机设计

**状态转换图**：
```
AI服务 → 待教师接入 → 教师服务 → 已解决 → 已关闭
    ↓           ↓           ↓
  转人工      教师接单      教师退出
```

**技术实现**：
1. 5种会话状态：AI服务、待教师接入、教师服务、已解决、已关闭
2. 状态转换事件驱动
3. 系统消息记录每次状态变更
4. WebSocket实时同步状态变化

### 6.3 RAG检索优化

**两阶段检索策略**：
1. **语义检索**：使用通义千问embedding模型进行向量化
2. **重排序**：使用qwen3-rerank对结果进行重排序

**个性化检索**：
1. 传入用户学院、校区、班级等上下文
2. RAG优先匹配与用户相关的内容
3. Prompt引导AI使用个性化信息

### 6.4 实时通信架构

**技术选型**：
- WebSocket协议
- Centrifugo作为WebSocket服务端
- 支持集群部署和消息持久化

**应用场景**：
1. 教师介入时学生消息实时推送
2. 会话状态变化实时同步
3. AI流式回答实时推送

## 十、常见面试追问准备

### Q1：为什么选择FastAPI而不是Spring Boot？

**准备要点**：
1. FastAPI原生支持异步，处理SSE和WebSocket更自然
2. 类型注解和自动文档生成能力
3. 深度集成Dify Python SDK，避免跨语言调用
4. Spring Boot在企业级应用中更成熟

### Q2：Dify和直接调用OpenAI API有什么区别？

**准备要点**：
1. Dify提供可视化Chatflow编排
2. 知识库管理、RAG检索、对话历史管理
3. 支持自托管，保证数据安全
4. 降低LLM应用开发门槛

### Q3：如何保证AI回答的准确性？

**准备要点**：
1. RAG检索知识库，减少幻觉
2. 检索分数阈值，低置信度转人工
3. 知识库迭代机制，持续优化
4. 个性化检索，精准匹配用户需求

### Q4：WebSocket在项目中的作用是什么？

**准备要点**：
1. 教师介入时消息实时推送
2. 会话状态变化实时同步
3. AI流式回答实时推送
4. Centrifugo保证消息可靠传递
